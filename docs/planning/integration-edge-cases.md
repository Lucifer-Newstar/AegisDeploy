# Integration Edge Cases & Lead Decisions (P2)

> **What this is:** issues that only appear at the *boundaries between
> members* — invisible inside any single track, guaranteed to bite at
> integration time. The Team Lead (Navin) owns each row's decision. Reviewed
> at the weekly sync; new rows are appended as tracks surface them.
> Source of truth: [p2-kickoff.md](p2-kickoff.md) · [phases.md](phases.md) §4.

**How the lead runs this register:**
1. Weekly sync: walk the table, move `Due` dates, add rows from new PRs.
2. Anything changing a contract, envelope, or runtime parity needs a
   decision row here (or in the planning decision log) — never silent.
3. The register is a working doc: rows close when the mitigation lands
   (checked in the same PR), not when they're "agreed".
